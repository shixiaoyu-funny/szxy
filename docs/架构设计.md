# 数智乡约 —— 软件设计说明

> AI 驱动乡村振兴服务平台 的设计说明文档，涵盖技术栈、系统架构、模块划分、鉴权设计与数据模型。

## 一、技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 后端框架 | Spring Boot 3.5（JDK 17） | RESTful API 服务 |
| ORM | MyBatis-Plus 3.5 | 数据访问、分页、枚举强类型 |
| 数据库 | MySQL 8 | 关系数据存储 |
| 缓存 | Redis 7 | 会话、榜单缓存、UV 统计 |
| 消息队列 | RabbitMQ 3.12 | 验证码异步发送、订单延迟取消、定位推荐 |
| AI | Spring AI（通义千问 qwen3.8-flash） | 多模态对话、工具调用、联网搜索 |
| 前端框架 | Vue 3 + TypeScript | 组合式 API SPA |
| UI 库 | Element Plus | 组件化界面 |
| 构建 | Vite 7 | 开发构建、代理 |
| 状态 | Pinia / 自制 store | 用户会话状态 |

| 包 | 职责 |

## 四、鉴权设计

采用 **Redis + UUID 无状态 Token**，不依赖 Spring Security。

1. **登录**：登录接口校验后生成 UUID token，用户信息 JSON 写入 Redis（TTL 6h），前端以 `access_token` 请求头携带。
2. **三档路径拦截**：
   - `exclude-path`：登录/文档，完全放行。
   - `optional-path`：浏览类接口，有 token 识别身份、无 token 放行（游客浏览）。
   - 其余：强制登录，未登录 401。
3. **登录拦截器**：每请求从 DB 刷新最新角色/状态（禁用即拒、任命即时生效），续期回写。
4. **管理端双保险**：`AdminInterceptor` 拦截 `/report/**`（role≠4 返回 403）+ Service 层 `SecurityUtil.requireAdmin()` 兜底。

## 五、核心业务设计

1. **角色体系**：`user.role`（1游客/2农户/3村长/4管理员）强类型枚举；村长另由 `village_base.manage_id` 指向，与 role 事务内同步。
2. **商品交易**：`shop_product` 区分实体/门票核销/住宿核销；下单同步落库，余额支付采用 CAS 乐观更新；15 分钟未支付由延迟队列自动取消。
3. **准入审批**：游客→农户（管理员审批）；农户→村长（村长初审 + 管理员终审），双级审批。
4. **AI 助手**：Spring AI + 通义千问，支持多模态（文本+图片）、函数工具（乡村/景点查询、订单购物车、联网搜索）；游客匿名聊天不落库。
5. **流量统计**：`FreshInterceptor` 拦截记录 PV/UV，UV 用 Redis HyperLogLog。

## 六、数据模型（17 张表）

| 表 | 说明 |
|---|---|
| user | 用户账号（角色/状态/余额/定位偏好） |
| village_base | 农村基础信息（含村长 manage_id） |
| farm_user | 农户档案（关联 user 与村落） |
| village_scenic | 景点信息 |
| user_comment / user_like / user_collect | 评论 / 点赞 / 收藏 |
| farmer_access / vghead_access | 农户准入 / 村长准入申请 |
| shop_product | 可售商品（实体/门票/住宿） |
| cart_item | 购物车 |
| trade_order / order_item | 订单 / 订单明细 |
| wallet_record | 钱包流水 |
| user_address | 收货地址 |
| chat_session / chat_message | AI 会话 / 消息 |

完整建库脚本见 `szxy-backend/src/main/resources/db/xiangyue_full.sql`。
